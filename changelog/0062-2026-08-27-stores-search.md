# Changelog 0062 — Search box on the Stores (and Positions) page

- **Timestamp:** 2026-08-27 (AST, UTC-4)
- **Requested by:** Arif
- **Task:** Add a search option to the stores addition page.
- **Status:** Applied (frontend only; no schema/API change).

## What changed
- **`staff_frontend/lib/screens/org_child_list_screen.dart`** — the shared
  Stores / Positions list (reached from Brands & Stores → Stores). Added a
  **name search** field above the existing "Filter by brand" dropdown:
  - A `TextField` (magnifier prefix, clear `×` suffix once typing) labelled
    "Search Stores" / "Search Positions"; filters the list case-insensitively by
    `label.contains(query)`, combined (AND) with the brand filter.
  - New state `_searchCtrl` + `_query`, disposed in a new `dispose()`.
  - The empty state is now context-aware: with an active search or brand filter
    it reads "No Stores match your search." and offers a **Clear filters** button
    (resets query + brand) instead of the misleading "No Stores yet." + Add.
  - Because the screen is shared, **Positions** gets the same search for free.

## Verification
- `flutter analyze lib/screens/org_child_list_screen.dart` — no new issues
  (only the pre-existing `use_build_context_synchronously` info in
  `_deleteSelected`).
- `flutter build web` — succeeds. Used the non-outlined `Icons.filter_alt_off`
  (not `_outlined`) to avoid the icon tree-shaker drop documented in 0053.
